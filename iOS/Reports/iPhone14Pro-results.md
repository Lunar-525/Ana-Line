# iPhone 14 Pro 真机测试结果

Release 真机快速测试和十二分钟持续测试均已完成。现有 AnalogCore 全部源文件无需修改算法即可在 iOS 编译；音画信号链运行正常并保持锁定，但当前完整精度的电视链路没有足够的持续实时性能余量。

设备：iPhone 14 Pro（iPhone15,2）；系统：Version 27.0 (Build 24A435)；USB 有线连接；Swift 6、Release `-O`，直接启动，无调试器。没有采集电池电量、充电状态、环境温度或屏幕亮度。

快速测试开始：2026-10-12T03:55:06+08:00。快速测试每场景 30 秒，持续测试每场景 180 秒，依次为默认 PAL、损伤 PAL、默认 NTSC、损伤 NTSC。持续测试紧接快速测试，无冷却间隔，所有采样时系统热状态为 serious（2）。没有直接测量温度或 CPU 频率。

两轮合计 14,702 个测量帧，所有帧锁定并通过 RGB/PCM 有限值及伴音样本数检查。持续测试峰值内存约 82.5 MB。有效性检查不表示 RGB 或音频波形与参考实现逐样本一致。

测试使用固定彩条与连续 1 kHz PCM，逐帧执行 CVBS 编码、统一图像/伴音 RF 链路与 RGBA 转换，前三帧预热不计入结果。损伤场景参数固定在 BenchmarkApp.swift。预览每秒更新一次，伴音参与计算但不播放。处理耗时不含视频解码、实际音频播放、每帧 UI 呈现、数据检查、JSON 写入和等待；因此这不是完整播放器验收。采样及每秒报告写入仍会占用测量区间外的时间，并影响整体负载。过载时保持连续源帧，不实施跳帧策略。

移植判断：胶片、SSTV 可作为首批移动端功能。电视模式保持现有精度及制式原速，需要优先细分剖析 RF 链路，再评估批量 FIR、重采样等计算的优化/GPU 路径。也可先支持离线处理或提供性能档位。不能用短时默认 NTSC 的结果承诺持续实时。本测试没有证明其他机型无法实时，也没有证明 GPU 改造必然足够。
