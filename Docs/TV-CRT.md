# 地面电视 CRT 显示器

点击地面电视顶部的白色 **CRT** 按钮，在仪器风格面板中启用「CRT 显示器」，再打开「HDR 荧光粉亮度」。默认启用「自动 XDR 亮度」，峰值跟随当前屏幕的实时 EDR 余量；关闭自动后可通过金属旋钮调节到该屏幕的潜在上限。实际输出始终受实时可用余量限制。设置保存在本机。

滤镜作用于原图／处理后对比中的「处理后」区域。将分隔线拖到最左侧可查看完整 CRT 画面。扫描线默认自动跟随模拟 CRT 行数；关闭「自动扫描线」后，可用旋钮或点击数码读数输入 120 条到当前广播标准的可见行数，双击旋钮恢复 480 条。设置即时生效并保存在本机。

电视控制栏的 **Clean Feed** 会打开一个独立窗口，也可以从 **Window → Clean Feed**（⇧⌘L）打开。窗口只显示处理后的节目画面：没有原图／处理后分隔线、标签、扫描进度或 OSD。它跟随主窗口的 CRT 设置；与主窗口共享同一播放／接收会话，无视频时显示纯黑。窗口大小可调整，画面保持宽高比并在黑底上居中。

Clean Feed 由 AppKit 管理窗口生命周期：关闭后宿主视图和 Metal 渲染器会被释放，再次点击按钮会创建新的窗口与渲染器，而不是复用 SwiftUI 单例 `Window` 场景的旧内容。回归验证：`swift test --disable-sandbox --filter TVCleanFeedWindowTests`。

## 像素模型

显示层不再把连续画面乘上一张彩色遮罩、再除以遮罩平均透过率。接收机的 SDR 帧会先被重采样到一块模拟荧光点阵：

- `CRT 行数` 决定垂直方向的模拟像素数；水平三元组数由显示宽高比推导，所以一个模拟像素始终是一组 R/G/B 荧光点。
- 每个模拟像素按覆盖面积采样一次源画面（GPU 在四个位置采样，并按像素尺寸选择 mipmap 级别）；三个荧光点共享该像素的 R/G/B 值，但每个点只发射自己的基色。
- 一组三元组积分回原来的颜色。屏幕像素可以同时收到相邻 R/G/B 点的光，但每个点本身只发一个通道。
- 不同排列使用不同形状的暗缝：荫栅只有垂直暗缝，荫罩/槽孔/一字点在两个方向都有暗缝。`荧光粉栅格` 控制开口大小。
- 同基色辉光只从相邻的同色荧光点取样，红光不会漏成绿光。
- 当模拟点小于一个显示像素时，显示层淡出为三元组的平均色，避免摩尔纹和彩色噪声。因此行数越高，点阵越接近屏幕像素极限并自然消失。

栅格不再用平均透过率做归一化。每个点的驱动是线性的，平均亮度约等于：

```
源亮度 × 该排列的开口率 × 荧光粉峰值
```

（扫描线、暗角和 HDR 峰值上限还会进一步影响实际平均值。）点状荫罩的开口率通常低于荫栅，因此同样峰值下更暗，这是排列本身的物理差异。提高 `荧光粉峰值` 可在 EDR 余量内补偿。旧实现中「亮部没有余量时降低栅格强度以保留平均亮度」的补偿逻辑已经移除，因为它会把三个通道重新混回去，不再是像素发光。

## 荧光点排列

面板的「荧光点排列」提供七种结构，每一项左侧都有对应排列的示意图：

- **荫栅 / Aperture grille**（Sony Trinitron、Mitsubishi DiamondTron、ViewSonic SonicTron）：连续垂直 R/G/B 荧光条，垂直方向没有暗缝；屏幕上有 1–2 条水平阻尼线。亮度和色纯度较高。
- **荫罩 / Shadow mask (dot triad)**：金属板上的圆孔，荧光点按三角形三元组排列；经典 RCA 荫罩。点与点之间两个方向都有暗缝。
- **槽孔荫罩 / Slot mask**（如 NEC CromaClear）：把圆孔拉长成垂直槽孔，相邻行交错半个槽；比点状荫罩开口率更高、更亮。
- **一字点荫罩 / Inline shadow mask**：三色荧光点在水平方向排成一条直线，点被垂直拉长；常见于 in-line 电子枪。

新增的三项沿用相同的“示意图＋标题＋说明＋选择状态”列表行：

- **六边形荧光单元（实验）**：RGB 六边形单元采用交错三角晶格，黑色间隙随栅格强度变化。区别于“圆点中心按六角排列”。来源：[US6166486](https://patents.google.com/patent/US6166486)。有专利依据，不据此宣称为常见量产结构。
- **横向 RGB 条纹（实验）**：RGB 条带沿水平方向延伸，沿垂直方向重复；不绘制竖向分色和阻尼线。来源：[US6479937B2](https://patents.google.com/patent/US6479937B2/en)。实现荧光屏外观，不仿真束索引控制电路。
- **束索引竖条屏**：连续 RGB 竖条，有色条间隔，无荫栅阻尼线；背面索引层不画成可见的第四种色条。来源：[SID Beam-index cathode-ray tubes](https://sid.onlinelibrary.wiley.com/doi/full/10.1002/j.2637-496X.1990.tb05911.x)。这是显示外观预设，不仿真索引反馈与黑位电流。

现有三角圆点改为跨网格边界连续的三角晶格，不再在每个方形单元内孤立放置三个圆点；平均每模拟像素三个荧光点。六边形单元共用该晶格和 RGB 分色。旧四种排列的持久化编号 0–3 保留，新项追加为 4–6。

七种排列共用模拟像素网格，只有 aperture 形状、主色分配和阻尼线不同。`荧光粉栅格` 控制开口大小；荫栅在 0% 时仍保留阻尼线。

## 参数

- `CRT 行数`：120 到当前广播标准的可见行数，默认 240。PAL 上限 576，NTSC 上限 480。数值越低，荧光点越大、像素感越明显；数值越高，画面越接近源分辨率，但点阵会逐渐小到屏幕无法分辨。
- `荧光点排列`：荫栅、三角圆点、槽孔荫罩、一字点荫罩、六边形单元（实验）、横向 RGB 条纹（实验）、束索引竖条。每项提供独立示意图和说明。
- `荧光粉栅格`：0–100%，默认 80%。控制荧光点占单元的面积；越高暗缝越宽，平均亮度越低。
- `自动 XDR 亮度`：默认开启，使用实时可用 EDR 余量。
- `荧光粉峰值`：手动模式为 1× 到屏幕潜在余量，保留原手动设定（初始 2×）。实际输出上限取 `min(屏幕 EDR 余量, 设定值)`；关闭 HDR 时为 1×。
- `自动扫描线`：自动跟随 `CRT 行数`；关闭后使用手动扫描线数量。扫描线条数与荧光点行数不必一一对应，真实显像管也相互独立。
- `扫描线数量`：手动模式 120 到当前广播标准的可见行数，默认 480。

`CRT 行数` 和手动扫描线都受当前广播标准的可见行数限制（PAL 576 / NTSC 480），切换标准后会立即收紧。渲染时还会取窗口实际像素高度与标准上限的较小值，因此小窗口不会请求超过其显示能力的行数。

## 显示与 HDR

接收机输出仍是 SDR。显示层将带色彩配置的图像转换为 sRGB，GPU 在线性光中处理扫描线、荧光点孔径和同基色辉光，最终写入 `rgba16Float`、`extendedLinearSRGB` 的 Metal 显示层，开启 `wantsExtendedDynamicRangeContent`。亮荧光点可输出大于 1 的值；黑色保持为零。这是 CRT 发光的 HDR 呈现，不是恢复原始视频中已经丢失的 HDR 信息。

每次绘制读取窗口所在屏幕的 `maximumExtendedDynamicRangeColorComponentValue`；暂停时也定期检查余量变化。SDR 屏幕或不可用的 EDR 余量会限制到 1。没有 Metal 时回退为普通图像预览。OSD 和原图保持原有显示方式。

曲率作用在图像空间，荧光点阵也随画面轻微弯曲，而不是固定贴在窗口上的网点纸。每次画面更新时生成 mipmap，点阵采样使用导数选级，缩小或播放运动画面时不会退回点采样。

## 球面畸变

`Curvature` 控制 CRT 球面／桶形畸变，范围 0–100%，默认 50%：

- 0%：完全平直，关闭球面畸变；
- 50%：等于之前固定的曲率系数 `k = 0.018`；
- 100%：更强的桶形，`k = 0.036`。

曲率同时作用于主预览、Clean Feed、玻璃边缘与摄像头反射的映射；摩尔纹检测用同一个系数缩放局部拉伸采样。调整曲率后警告会即时重算。

## 条纹点对点

横竖条类遮罩（荫栅、槽孔、一字点、横向 RGB 条纹、束指引竖条）默认使用「条纹点对点」：

- 每个 RGB 条纹必须落在整数个显示像素上：条纹宽 `1 px`、`2 px`、`3 px`……，而不是任意小数；
- 当整数光栅小于 drawable 时居中显示并保留黑边；不会为了填满窗口回到小数缩放；
- 请求行数超过该预览能容纳的整数条纹上限时，实际行数会被压低，而不是产生小数条纹。640×480 上限 160 行，1280×960 上限 320 行，1920×1440 上限 480 行；
- 该模式会旁路球面曲率和玻璃／反射，因为曲面会让条纹相位重新变成非整数；扫描线跟随实际行数，手动扫描线旁路；三角／六角排列不受影响，仍可自由缩放。

行数越低，整数倍率越大：1920×1440 下 120 行是 4×、240 行是 2×、480 行是 1×。因此低行数也能填满画面；行数变化时看到的是整数倍率/黑边变化，不应再出现小数条纹拍频。

### 最佳全幅行数

全幅（无黑边）的最佳行数不是简单的 `H / 3`，而是要同时满足整数条纹和广播标准行数上限。对 4:3 的 drawable：

```
cap      = min(W / 4, H / 3)             // 1px 条纹时的全幅行数
k        = ceil(cap / 标准上限)           // 最小整数条纹宽度
L_best   = floor(cap / k)                // 标准内最大的全幅行数
```

例如全屏 Clean Feed 的 4:3 图像区为 2936×2202 时，`cap = 734`；PAL 上限 576，所以 `k = ceil(734 / 576) = 2`，`L_best = floor(734 / 2) = 367`。734L 虽然能 1px 填满，但超过 PAL 576；576L 在 1px 下只能显示 1728px 高，上下会留黑边。367L 是 2px 条纹下的最大全幅，因此在 PAL 标准内效果最好。若图像区高度是 1101，则 k=1，同样得到 367L。

常见 4:3 drawable（物理像素）下的最佳全幅行数：

| 4:3 图像区 | PAL 576 | NTSC 480 |
|---|---:|---:|
| 640×480 | 160L / 1px | 160L / 1px |
| 1280×960 | 320L / 1px | 320L / 1px |
| 1440×1080 | 360L / 1px | 360L / 1px |
| 1920×1440 | 480L / 1px | 480L / 1px |
| 2133×1600 | 533L / 1px | 266L / 2px |
| 2880×2160 | 360L / 2px | 360L / 2px |
| 2936×2202 | 367L / 2px | 367L / 2px |
| 3840×2880 | 480L / 2px | 480L / 2px |
| 4512×3384 | 564L / 2px | 376L / 3px |

Retina 屏幕上表要使用 drawable 物理像素，而不是窗口 point 尺寸。CRT 面板会显示当前预览的最佳全幅值，并提供「使用」按钮。

## 摩尔纹警告

电视预览使用 Metal drawable 的实际物理像素尺寸评估摩尔纹风险，随预览尺寸和屏幕 backing scale 更新。提示为覆盖层，不改变预览尺寸；低风险为白色信息条，中/高风险为黄色警告。Clean Feed 不显示提示。

评估复用渲染器的行数上限、RGB 三元组和遮罩开口参数，分别估计扫描线与遮罩的风险：

- 依据屏幕像素中的周期、非整数采样间距与曲面局部拉伸估计密度和拍频风险；
- 纳入 shader 的扫描线淡出和无法分辨荧光点时的平均色回退，避免对已淡出的点阵报警；
- 自动扫描线随 CRT 行数变化，手动扫描线独立评估；
- 三角/六角密排使用更低的遮罩风险权重，并跳过方形行拍频项；三色在二维交错，实际可比竖条更晚出现可见摩尔纹；
- 分数低于 0.2 为低风险，0.2 至 0.55 为中风险，其余为高风险。这些是启发式阈值，未经视觉实验标定；整数比例不保证低风险；
- 推荐附近能降低风险分数至少 0.12 的较低 CRT 行数，不通过增加行数让点阵消失来换取低分。手动扫描线不随建议改变；遮罩风险无有效行数建议时提示放大预览，扫描线风险提示减少扫描线或放大预览。

这是几何采样预测，不分析逐帧内容；低风险不保证实际画面没有摩尔纹。源纹理、显示器子像素排列和观看距离不在模型内。

## 可见性与限制

真实显像管在正常观看距离下通常看不出单个荧光点；能清楚看到点阵的效果本质上是宏观／近摄的 CRT。当前预览也一样：

- 240–360 行时，2× 屏幕上的荧光点通常还能分辨，适合观察像素结构。
- 480 行以上时，单个点会接近或小于一个显示像素，显示层会淡出为平均色，点阵看起来更像细微的彩色纹理。
- 模拟行数由 `CRT 行数` 决定，不随窗口放大而增加；窗口小于该行数时，渲染会按实际像素高度收紧。水平三元组数只随宽高比调整。

当前只作用于视频预览与 Clean Feed 窗口；无信号雪花、复制图像及导出视频不包含此显示滤镜。实际峰值亮度取决于屏幕亮度、显示模式和系统提供的 EDR 余量。

## 验证

`swift test --disable-sandbox --filter TVCRTDisplayTests`。

`swift test --disable-sandbox --filter TVMoireAdviceTests` 验证物理像素尺寸、遮罩差异、手动扫描线、回退保护、行数上限和建议改善幅度。

测试在 GPU 上编译 shader、渲染并读取半浮点纹理，覆盖：

- 每个荧光点只发一个基色，另外两个通道为零；
- 七种排列的示意图都绘出红/绿/蓝三种荧光点；
- 七种排列的三元组平均亮度分别等于各自的开口率 × 峰值，不再归一化为 1；
- 峰值线性缩放，HDR 白色超过 1、SDR 白色不超过 1、黑位为零；
- 高行数下点小于显示像素时回退为中性平均色；
- 三角/六角在相同尺寸和行数下比竖条更晚进入高风险；
- 曲率 0/50/100% 的系数钳制，以及关闭曲率只移除局部拉伸采样；
- 条纹点对点的行数上限、整数倍率、黑边和超限压行；
- 最佳全幅行数公式，包括 2936×2202 / PAL 下的 367L；
- 手动扫描线数量改变实际渲染密度；
- 行数与扫描线不超过当前广播标准和窗口像素高度；
- 根据实际显示采样条件给出分级摩尔纹风险；
- 余量限制、异常数值回退、行数与填充率参数。

## 自动 XDR 亮度

HDR 开启时默认启用“自动 XDR 亮度”（`tvCRTAutoBrightness`），每次绘制使用所在屏幕的实时 EDR 余量作为荧光峰值倍率，取消原来的 4× 上限。主预览与 Clean Feed 分别读取各自屏幕。手动模式保留 `tvCRTBrightness`，请求值受当前屏幕潜在余量约束，实际输出仍不超过实时可用余量；HDR 关闭时上限为 1×。

面板读数来自主预览实际渲染使用的参数：请求、输出上限、可用与潜在余量。输出上限不是测得的画面峰值或尼特数，遮罩开口、扫描线和内容仍影响实际像素值。没有正在渲染的预览时无法取得新读数。

暂停画面每秒检查屏幕余量变化，窗口 backing properties 变化也会触发重绘。检查定时器使用 common run-loop mode，使窗口交互期间仍可更新。既有手动倍率保留；未设置自动模式偏好的用户默认进入自动模式。

测试覆盖自动 12×、手动 16× 请求的实时限制、SDR 和异常读数回退，并在 GPU 半浮点渲染目标验证 16× 请求产生高于 4× 的像素。此项验证不等于物理面板亮度测量。

## 电子束、短余辉与会聚

“电子束与荧光响应”使用现有机架旋钮样式，设置与其他 CRT 参数一样保存在本机，主预览和 Clean Feed 共用设置。面板可以滚动，七种排列及新旋钮在较小屏幕上均可访问。

| 参数 | 范围／默认 | 行为 |
| --- | --- | --- |
| 电子束光斑 | 0–2 源像素／0.35 | 亮部的取样光斑更宽，边角聚焦略软；亮部扫描线间隙随光斑增宽而收窄。0 恢复原始聚焦与扫描线调制。 |
| 边角会聚误差 | 0–3 源像素／0.25 | 红蓝取样位置向相反方向偏移；误差随离中心的距离增加，绿色作为参考。0 关闭。 |
| 荧光衰减时间 | 0–80 ms／18 ms | 红通道的指数衰减时间常数，绿／蓝分别取该值的 0.85／0.7；0 关闭余辉并释放历史缓冲。 |

这些是未按具体显像管标定的显示近似。光斑变化和 RGB 会聚作用于源图像的线性光取样，屏幕上的物理荧光排列保持固定。高行数进入平均色回退时，光斑和会聚仍然生效。会聚模式也适用于实验性排列；束索引预设只近似落点偏差，不模拟其控制电路。

余辉在 CRT 发光之后、屏幕像素坐标中处理。为每个输出独立分配一张当前发光纹理和两张交替的半浮点历史纹理，第二次绘制同时写显示目标与下一张历史，不回读 CPU。每通道采用：

```
光强 = max(当前激发光强, 上次光强 × exp(-真实经过秒数 / 时间常数))
```

该模型表现快速激发、指数衰减，不将帧相加，因此静止图像不持续增亮。RGB 时间常数比例是短余辉艺术预设，不代表某种实测荧光粉配方。上限始终服从当前 EDR／SDR 限制。

有新图像时按 60 Hz 刷新余辉；暂停后最多继续 8 个红通道时间常数，再恢复按需绘制。它不是逐行脉冲扫描仿真，也不保证在现代面板上重现真实 CRT 的运动清晰度。刷新间隔不参与设定时间常数。

换源、跳转、重新从片尾播放、切换制式、改变排列／显示参数、改变窗口像素尺寸和输出峰值时重置历史。跳转仍在等待新图像时不保留旧画面的发光历史。关闭、重开 Clean Feed 时重建该窗口的历史，不与主预览互相污染。

`TVCRTPhosphorTests` 在 GPU 上验证真实时间衰减、不同刷新间隔的一致性、静止光强不累加、HDR 到 SDR 上限、重置与缩放；空间测试检查亮暗光斑宽度、边角焦点以及中央和边角 RGB 分离程度。原有七种排列与开口率回归使用零光斑／零会聚参数，验证原渲染仍可恢复。

## 玻璃散射、光晕与摄像头反射

“玻璃散射与反射”在荧光余辉之后执行，主预览和 Clean Feed 都可使用：

- **玻璃散射**：0–100%，默认 12%。将部分屏幕光重新分配到较窄与较宽的扩散层；均匀画面亮度保持不变。
- **高光光晕**：0–100%，默认 18%。先对当前实际发光值做软阈值高光提取，再生成多级模糊，向周围添加低强度光晕。不是对整帧统一加亮，最终输出仍受 EDR／SDR 上限约束。
- **光晕半径**：2–40 个 PAL 参考像素，默认 12，随实际 drawable 高度缩放。
- **相机反射强度**：0–30%，默认 8%。只有独立的“实时摄像头玻璃反射”开关开启且有可见 CRT 输出时才采集；新安装默认关闭。

摄像头倒影做水平镜像、宽高比裁切、柔化和曲面映射，边缘反射略强、亮部反射略弱。反射光保持 SDR 范围，不乘 XDR 荧光倍率。散射、高光光晕与倒影都不写回荧光历史，关闭相机后不会留下倒影余辉。摄像头是粗略的房间反射代理，没有做真实三维环境重建或视线追踪。

macOS 摄像头权限仅由上述显式开关触发；须运行打包的 `build/AnaLine.app`，其 Info.plist 包含 `NSCameraUsageDescription`。SwiftPM 可执行程序和测试运行器缺少该键时显示运行打包应用的提示，不调用权限请求 API。拒绝权限、无设备或采集中断时给出说明，普通散射和光晕继续工作。

相机优先选择内置 FaceTime 摄像头，无内置设备时使用系统默认视频设备。当前机器检出 FaceTime HD Camera 与 OBS Virtual Camera，因此优先使用前者。只创建视频输入和内存视频输出，不创建音频输入或录制输出，不写文件、不上传；画面也不进入复制图像或视频导出。采集配置和启动在专用串行队列执行，目标 640×480／15 fps，只保留最新一帧；晚帧丢弃，超过一秒没有更新的帧不再显示。

两个输出共享同一采集会话，各自保留 Metal 纹理包装，直到 GPU 完成读取。最后一个可见 CRT 输出关闭、最小化或被完全遮挡时停止采集并清空最新帧；独立反射开关关闭或强度为 0 也停止需求。重新变为可见且开关仍开启时恢复。系统权限撤销和相机中断会停止会话，可切换开关重试。

`TVCRTGlassTests` 使用合成像素缓冲而非真实相机，验证镜像方向、暗部反射更明显、无帧时清理、反射不进入余辉、散射的均匀场保持、光晕的空间扩散与暗部阈值，并覆盖缺少相机用途声明时不请求权限的路径。
